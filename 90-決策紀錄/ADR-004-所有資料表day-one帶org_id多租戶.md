# ADR-004：所有資料表 day-one 帶 org_id（多租戶預留）

- 日期：2026-08-12｜狀態：採納

## 脈絡
Phase 1–2 只有自家一個機構使用；Phase 3 規劃開放平台（多機構或 SaaS 化）。單租戶 schema 改多租戶是全面重構（每張表、每條 RLS、每個查詢）。

## 決策
自第一張表起，所有資料表帶 `org_id` 欄位＋RLS 租戶隔離 policy，即使目前只有一個 org。

## 理由
1. 現在的成本是每張表多一欄＋一條 policy（一天內）；日後補做是數月的遷移與回歸測試
2. RLS 租戶隔離同時是資安縱深：即使應用層出錯，資料庫層仍擋跨機構存取
3. Supabase 的 RLS 模式天然支持此設計，無額外複雜度

## 後果
- 所有查詢都要帶 org 脈絡（以 JWT claim 注入，開發框架統一處理，避免每處手寫）
- 自動化測試必含「跨 org 存取被拒」案例
