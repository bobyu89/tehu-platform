# 特護平台 tehu-platform

台灣特別護理師（特護）服務平台：一套系統同時處理**行政**（需求進線、派單、打卡、工時、客訴）與**照護**（生命徵象、三層異常警報、交班、給藥、傷口）。營運主體（自建護理機構或與合法機構合作）待律師確認，之後開放給其他機構（見〈01〉§2）。

本 repo 包含完整的產品規劃書（00–09 冊、決策紀錄）與可操作的網頁原型（`app/`）。

## 線上示範

**https://bobyu89.github.io/tehu-platform/**

原型以側欄「切換視角」示範三端，資料存在瀏覽器本機，打開就有示範資料在運轉：

| 端 | 入口 | 給誰用 |
|---|---|---|
| 公司管理端 | [/console/](https://bobyu89.github.io/tehu-platform/console/) | 護理長、調度、行政：總覽、需求進線、派單、出勤、績效、客訴、警報中心、個案照護、衛教、家屬日報、電子簽章、數據分析 |
| 照護人員端 | [/staff/](https://bobyu89.github.io/tehu-platform/staff/) | 護理師本人：今日班次與接案、案件紀錄、我的檔案、收入 |
| 客戶端 | [/client/](https://bobyu89.github.io/tehu-platform/client/) | 付費家屬：我的個案、照護人員與評價、提出需求 |

> 示範資料皆為虛構。介面用語遵守醫材紅線：系統做的是「紀錄、提醒、彙整」，不做診斷。

## 目前進度

**階段：離線示範原型。** 前端功能齊全、可實際操作；尚未連接後端（Supabase）、沒有登入，也還沒有串接 LINE、簡訊或 AI。

已完成：

- 三端介面與主要流程（派單狀態機、打卡審核、交班簽收、給藥 MAR、傷口紀錄、衛教推送、電子簽章存證）
- 警報判定引擎：
  - A 層：絕對臨界值、尿量、質性紅旗
  - B 層：NEWS2，計分與分級對齊 RCP 2017
  - C 層：個人基準線，永不發紅色
- 派單硬條件：技術標籤、輪班間隔 ≥ 11 小時（勞基法）
- 目標資料庫 schema：`supabase/migrations/`，含多租戶隔離、append-only、依權限矩陣的 RLS（有自動化測試）
- 離線同步佇列：床邊紀錄寫入本機時排入佇列，同步引擎可依序送往 Supabase（尚未接上後端）
- 單元測試 135 項；CI 會跑型別檢查、lint、測試、建置，並套用 migrations、執行 RLS 權限測試與同步契約測試

下一步與完整待辦見〈[10 技術文件：現況實作](10-技術文件-現況實作.md)〉§10。

## 快速開始

需求：Node.js 24。

```bash
cd app
npm ci
npm run dev        # http://localhost:3000
```

Windows 可直接雙擊 `啟動特護平台.cmd`。送出變更前的檢查：

```bash
cd app
npm run typecheck && npm run lint && npm test && npm run build
```

## 專案結構

```
├─ 00–09-*.md、90-決策紀錄/     產品規劃書：為什麼這樣做
├─ 10-技術文件-現況實作.md      程式碼現在實際的樣子、與規劃的差異、待辦
├─ 11-公司簡介與品牌規範.md    公司名稱、定位、代表色、LOGO、標語、理念、視覺規範、官網架構
├─ 91-參考資料/                 外部討論與參考材料（非決策）
├─ CONTEXT.md                   共同語言：名詞、不變量、模組地圖
├─ app/                         Next.js 網頁原型（靜態輸出，部署到 GitHub Pages）
├─ supabase/migrations/         目標資料庫 schema（尚未部署）
└─ .github/workflows/           CI 與 Pages 部署
```

技術棧：Next.js 16（App Router、靜態輸出）、React 19、TypeScript、Tailwind CSS 4、Dexie（IndexedDB）、Vitest；目標後端為 Supabase（Postgres＋RLS）。

## 名詞表

| 名詞 | 定義 |
|---|---|
| 特護 | 特別護理師：自費一對一照護的護理師（醫院陪病或居家） |
| 個案 Case | 一位病人的一段服務關係（含需求、地點、方案） |
| 服務單 | 個案下的一段服務期間與計價方案 |
| 班次 Shift | 派單與打卡的最小單位（預設 12 小時） |
| 交班 Handoff | 上一班向下一班的結構化交接（ISBAR） |
| A/B/C 層 | 警報引擎三層：絕對臨界值／早期預警評分／個人基準線（平均線） |
| 質性紅旗 | 不經數值判斷、直通紅色警報的臨床徵象（如咖啡渣樣嘔吐物） |
